# Интеграция с платформой «Умный дом»

В существующем мобильном приложении добавляются видеозвонок с домофона, открытие двери и шлагбаума, управление разрешёнными автомобилями и добровольное подключение распознавания лица. Остальные функции приложения сохраняются.

Мобильное приложение обращается к `tenant-core-app`. Этот сервис проверяет собственника, квартиру, дом и УК. Новый `smart-home-integration` выполняет обмен с партнёром. Партнёр управляет домофонами и шлагбаумами. Мобильное приложение не получает служебные ключи партнёра и не обращается к устройствам напрямую.

| Область | Требование |
| --- | --- |
| Вход пользователя | Использовать существующий Keycloak, настроить клиент для мобильного приложения ЖКУ. Применять OpenID Connect и OAuth 2.0 Authorization Code с PKCE. Не хранить секрет OAuth-клиента в мобильном приложении. |
| Проверка запросов | Проверять подпись, издателя, получателя и срок access token. Идентификатор пользователя брать из проверенного токена. Переданный клиентом `user_id` не даёт прав на объект. |
| Права на объект | Проверять доступ к конкретным `uk_id`, `house_id` и `device_id` на сервере для просмотра видео, открытия и изменения разрешений. Партнёр также ограничивает данные и команды согласованным перечнем домов и устройств. |
| Доступ сервисов | Между интеграционным сервисом и партнёром использовать OAuth 2.0 Client Credentials и mTLS. Выделить отдельный клиент интеграции с правами `devices:read`, `doors:open`, `barriers:open`, `access:manage`. Не передавать пользовательский пароль партнёру. |
| Каналы | REST API по HTTPS с TLS 1.2 или 1.3 и проверкой сертификатов. Видеосвязь — WebRTC с защищённым медиаканалом и краткоживущим разрешением на конкретный домофон. |
| Состав данных | Передавать идентификатор привязки пользователя, устройства, разрешение, время действия, номер автомобиля для шлагбаума. Ф. И. О., паспорт, контакты, сведения о сделках и оплате ЖКУ для открытия не нужны. |
| Биометрия | До подключения распознавания лица определить правовое основание и получить необходимое письменное согласие. С юристом проверить требования 152-ФЗ и применимость 572-ФЗ к выбранной схеме. Сохранить открытие по звонку и через приложение без распознавания лица. |
| Хранение | Зафиксировать в договоре роли сторон, перечень данных, цели, сроки и места хранения, меры защиты, удаление и уведомление об инцидентах. Шифровать чувствительные данные и резервные копии. Трансграничную передачу отдельно проверить до запуска. |
| Шаблоны лица | В предлагаемой схеме партнёр хранит биометрический шаблон в отдельном защищённом хранилище. PropDevelopment хранит идентификатор привязки и состояние согласия. Не передавать изображения и шаблоны в DWH и обычные журналы. Это требование к партнёру необходимо подтвердить до подключения. |
| Секреты | Служебные ключи и сертификаты хранить в защищённом хранилище, ограничить доступ интеграционным сервисом. Предусмотреть ротацию и отзыв. Не включать секреты в исходники, URL и журналы. |
| Команды открытия | Передавать уникальный `command_id`, устройство и короткий срок действия. Партнёр проверяет полномочия, срок и повтор команды. Повторная отправка того же `command_id` не должна повторно открывать устройство. |
| События партнёра | Принимать события только от аутентифицированной платформы. Проверять подпись, время и `event_id`, отклонять повторы и события чужой УК. Успешная доставка команды не равна подтверждению открытия. |
| Ошибки связи | Ограничить время ожидания и число повторов. При неопределённом результате сначала запросить состояние команды. Недоступность партнёра не выдаёт новые права и не открывает дверь автоматически. Аварийные режимы здания работают независимо от интеграции. |
| Отзыв доступа | При продаже квартиры, смене УК, окончании разрешения или отзыве согласия удалять соответствующие разрешения и привязки у партнёра. Проверять подтверждение отзыва, а не только локальное изменение статуса. |
| Аудит | Фиксировать пользователя или сервис, УК, дом, устройство, действие, время, `command_id`, результат проверки прав и результат команды. Разделить право отправлять события и право читать журнал. Исключить пароли, токены, изображения лиц и полные номера автомобилей. |
| Проверка | Проверить доступ к чужому дому и УК, истёкший токен, повтор команды, отзыв разрешения, недоступность партнёра и удаление биометрической привязки. Сначала использовать тестовые данные и устройства. |

Схемы показывают предлагаемое изменение. Наличие перечисленных мер у партнёра не подтверждено исходным описанием.
